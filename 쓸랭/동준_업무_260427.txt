2026-04-27 작업 보고 (요약)                                                                                                                                                        
                                               
  1. AI 코드 검토 도구 연결                                                                                                                                                          
                                                                                                                                                                                     
  - 작성은 Claude, 검토는 Codex가 맡는 "이중 검토" 환경을 준비                                                                                                                       
  - 처음 호출이 계속 실패해서, 동작 가능한 모델을 찾아 기본값으로 고정 (앞으로 매번 모델 지정 안 해도 됨)
                                                                                                                                                                                     
  2. GitHub 저장소 만들기                                         
                                                                                                                                                                                     
  - 프로젝트 저장소에 골격을 첫 업로드                                                                                                                                               
  - 업로드 전 안전 점검: 비밀번호·API 키 같은 민감 정보가 실수로 올라가지 않는지 검사
  - 빠진 파일(빌드에 필요한 jar) 한 개 발견해서 같이 올림                                                                                                                            
  - "운영용 가지(main)"와 "개발 통합용 가지(dev)"를 분리해 두 브랜치 모두 업로드                                                                                                     
  - 이슈 보고서/변경 제안서 양식 추가 — 다음부터 깃허브에서 글 쓸 때 자동으로 빈칸이 채워짐                                                                                          
                                                                                                                                                                                     
  3. 잘못된 변경을 막는 규칙(Rulesets) 적용                                                                                                                                          
                                                                                                                                                                                     
  - 운영용 가지와 통합용 가지 모두에 "그냥 덮어쓰기 금지, 반드시 변경 제안서를 거치고, 자동 검증을 통과해야 합치기 가능" 규칙을 적용                                                 
  - 새 변경 제안서를 만들면 자동으로 통합용 가지로 향하도록 기본값 변경
                                                                                                                                                                                     
  4. 작성자 정보 정정                                             
                                                                                                                                                                                     
  - 처음 올린 두 변경의 작성자 정보가 잘못 박혀 깃허브에서 계정과 연결되지 않던 상태                                                                                                 
  - 올바른 정보로 다시 기록하고 덮어 올림 → 깃허브에서 정상 계정으로 표시 확인
                                                                                                                                                                                     
  5. 작업 방식 표준화 (변경 제안서 1건 생성)                      
                                                                                                                                                                                     
  - 두 가지 작업 방식을 도입하기로 결정                                                                                                                                              
    - TDD: "테스트를 먼저 짜고 그 다음 실제 코드를 만든다" — 보안/결제/포인트처럼 돈·계정과 관련된 곳은 무조건 적용
    - DDD: "비슷한 일을 하는 코드끼리 정해진 칸에 모으는 정리법" — 나중에 사람이 더 들어와도 헷갈리지 않게                                                                           
  - 일정상 무리 없도록 단순화한 버전으로 도입 (전부 엄격하게 X, 위험한 곳만 강하게)                                                                                                  
  - 코드가 얼마나 테스트되는지 자동 측정하는 도구도 같이 셋업                                                                                                                        
  - 이 결정들을 프로젝트 안내서에 적어 두어, 매 작업마다 자동 참조되도록 함
